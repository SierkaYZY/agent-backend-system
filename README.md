# Agent Backend System

A Python-based LLM Agent backend system built from the underlying tool-calling mechanism.

The project starts from manually implementing the core Agent workflow instead of relying directly on high-level Agent frameworks. It will gradually integrate RAG, FastAPI, PostgreSQL, evaluation, logging, Docker, and LangGraph.

## Current Status

The current version implements a minimal Tool Calling workflow:

1. Receive a user question.
2. Send available Tool Schemas to the LLM.
3. Let the LLM decide whether a tool is required.
4. Read the Tool Call generated by the LLM.
5. Parse the tool arguments.
6. Execute the corresponding Python function locally.
7. Send the Tool Result back to the LLM.
8. Generate the final answer.

The system also supports questions that do not require any tool.

## Current Tools

### add

Adds two numbers.

Example:

```text
User:
Please calculate 17.5 + 24.5 using the addition tool.

LLM Tool Call:
name = add
arguments = {
    "a": 17.5,
    "b": 24.5
}

Python Tool Result:
42.0

Final Answer:
17.5 + 24.5 = 42.0
```

## Tool Calling Flow

The LLM does not execute Python functions directly.

Instead, the workflow is:

```text
LLM decides to use a tool
        |
        v
Returns tool name + arguments
        |
        v
Python parses arguments
        |
        v
Python executes the real function
        |
        v
Tool result is sent back to the LLM
        |
        v
LLM generates the final response
```

For example:

```text
Tool Schema
    |
    v
LLM decides:
add(a=17.5, b=24.5)
    |
    v
Python executes:
add(17.5, 24.5)
    |
    v
Result:
42.0
```

### `agent/tools.py`

Contains the actual Python functions that can be executed by the Agent.

Current example:

```python
def add(a: float, b: float) -> float:
    return a + b
```

### `agent/tool_schemas.py`

Defines the Tool Schemas provided to the LLM.

The Tool Schema describes:

- Tool name
- Tool purpose
- Required parameters
- Parameter types

The schema does not execute the tool itself.

### `agent/runner.py`

Controls the current Agent workflow:

```text
User Question
    |
    v
LLM Request
    |
    v
Tool Call?
   / \
 No   Yes
 |     |
 |     v
 |   Execute Tool
 |     |
 |     v
 |   Tool Result
 |     |
 |     v
 |   Second LLM Request
 |     |
 v     v
Final Answer
```

### `api/main.py`

Reserved for exposing the Agent through FastAPI.

The future request flow will be:

```text
  |
  v
FastAPI
  |
  v
Agent
  |
  v
Tools / RAG / Database
  |
  v
Final Response
```

## Environment Variables

Create a `.env` file in the project root:

```env
DEEPSEEK_API_KEY=your_real_api_key_here
```

Never commit the real `.env` file to Git.

Use `.env.example` as the public template:

```env
DEEPSEEK_API_KEY=your_deepseek_api_key_here
```

## Learning Goal

The goal of this project is not only to build an Agent that works, but also to understand the complete execution flow behind an LLM Agent:

```text
LLM Decision
     |
     v
Tool Call
     |
     v
Argument Parsing
     |
     v
Python Execution
     |
     v
Tool Observation
     |
     v
LLM Decision
     |
     v
Final Answer
```

Later versions will extend this foundation into a complete LLM Agent Backend System.
